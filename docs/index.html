01 / DATA CLEANING先把数据洗干净

原始数据集标着“待清洗”，确实名副其实：179 人里 117 人没有性别、133 人身份“未标注”、 75 人与关系网络完全断开、180 张图有 20 组是同一张；关系表里还有把惜春记成贾珍之女这类世系错误。 下面每一类问题都给出了判定规则与处理结果。

117性别缺失

按亲属谓词（父/母/子/女）+ 主仆谓词（丫鬟/小厮）+ 原文考订逐条补齐，现 179/179 完整。

133身份未标注

重建为 主子／妾室／仆役／宗族／客卿／外人 六类，另加“身份细分”（丫鬟、小厮、管家、优伶…）。

75网络孤岛

原文“在关系网=否”。补 23 条文本可证的缺边（平儿、紫鹃、司棋、待书、抱琴…），59 人可由同场共现接回。

20同图多人的图源冲突

按 MD5 归并，一人一图；无法判定归属的整组标“图源冲突”，不硬凑。

关系谓词规范化

原表用了 70 余种谓词，其中大量是同义异写：丫环 / 丫头 / 大丫头 / 大丫环 / 陪房丫头 一律归并为 丫鬟；父→父亲、好兄弟/好朋友→朋友、相好/暧昧→私情。 归并后再按性别与语义自动生成互逆边（父亲↔儿子/女儿、妻↔丈夫、丫鬟↔主人）， 使“已配对”由原表的 94/188 提升到 293/348。

03 / STRUCTURE谁不可替代

关系网络极稀疏（密度 0.0102），109 人的巨连通块却只有 9 跳直径——一个“小世界”。 度、介数、PageRank 三种口径给出的答案并不相同，这正是多层网络有意思的地方。

贾宝玉

度 28、介数 0.214、有效规模 26.5、约束度 0.063——他是唯一横跨亲属、主仆、社会三层的枢纽， “结构洞”几乎全部经由他打通。

王夫人

度 13 却介数第二（0.087）。她连接的是“主子—仆役”过渡带（金钏、玉钏、彩云、周瑞家的）， 是荣国府内务的实际路由。

贾惜春

度只有 4，介数却排第四（0.048）。她与宁国府的血缘、与荣国府的居住、与佛门的归宿， 三重身份让她成为三块之间的“窄门”。

04 / COMMUNITY宗法结构的分形

在关系网络上做 Louvain，得到 9 个社群、模块度 0.632。它们几乎逐个对应“房头”： 宁国府、薛家、凤姐—琏二房、王夫人—元春、贾政—赵姨娘、秦可卿—秦家、邢夫人—邢家， 以及被单独切出来的“怡红院系”。

府邸只能解释 0.329（NMI），血缘解释 0.364。真正切分网络的不是“住在哪”， 而是“跟着谁吃饭”——宗法共同体的最小单位是“房”，不是“府”。

另一个值得注意的现象：把同样的算法用在文本同场网络上，模块度只有 0.144。 也就是说，小说的“舞台”本身是高度整合的——宝玉几乎和所有人同场；而制度性的亲属/主仆关系才是 把这张舞台切成碎块的力量。文本层的低模块度 × 关系层的高模块度，正是“人情社会的表层”与 “宗法结构的里层”之间的落差。

05 / TEXT LAYER被表格漏掉的人

原表 179 人里有 65 人没有任何关系边——包括平儿、紫鹃、司棋、待书、抱琴这些大丫鬟。 这不是她们不重要，而是编表时“只记主仆、不记丫鬟网络”。用 120 回全文的 400 字同场窗口重建后， 59 人可以接回主网。

文本层还给出一个反直觉的结果：丫鬟网络不是“星形”而是“链形”。以袭人为例，她与宝玉的同场次数极高， 但与晴雯、麝月、秋纹的同场次数同样高——怡红院内部是一个近乎完全图的小团体， 宝玉只是其对外接口。这也解释了为什么“宝玉—袭人”在介数上并不突出：捷径被内部稠密性抵消了。

06 / TIME舞台从谁身上移开

把 120 回切成 12 个十年块，重建每块的同场共现网络，能看到人物戏份的此消彼长： 袭人、晴雯在第 8 块（71–80 回）后急剧退场，紫鹃、王夫人在 81–100 回抬头，薛宝钗在最后两块回到中心。

07 / IMAGE MODALITY脸能不能解释位置

178 张剧照提取了亮度、饱和度、色彩丰富度、边缘密度与主色相，再与身份、网络指标对照。 结论有点扫兴但很诚实：视觉特征与网络位置几乎不相关（度—饱和度 r=0.024，度—亮度 r=-0.058）。

说明：原始图源分为 87 版剧照、工笔/绣像与带水印的网络图片三类，年代与风格不统一， 因此本页只做低层视觉统计，不据此推断人物形象。

08 / METHOD怎么复现

数据

原始三表 + 178 图（未改动，存 data/raw/）；全文来自公开的 120 回本 （data/external/hlm_master.txt，85 万字）；清洗与增补结果在 data/processed/， 人工考订明细在 data/curation/person_curation.csv，每一条都能追到依据。

方法

人物抽取：别名词典 + 最长匹配 + 泛称（珍珠、琥珀、彩云…）上下文过滤； 共现：400 字滑动窗口（同场）与章回级（证据）两套；社区：Louvain（关系层）； 中心性：NetworkX；布局：自实现 ForceAtlas2，静态图与网页共用坐标。

运行

pip install -r requirements.txt
python scripts/02_clean.py     # 清洗＋增补
python scripts/03_text.py      # 全文解析＋共现
python scripts/04_images.py    # 图像去重＋特征
python scripts/05_network.py   # 网络指标
python scripts/06_figures.py   # 静态图
python scripts/07_web.py       # 生成本页

局限

① 人物识别基于词典，别名遗漏会造成漏计；② 同场窗口是“阅读经验”的近似， 不是真的场景切分；③ 结局、部分关系为人工整理，依赖 120 回通行本；④ 图源冲突的 20 组只做了 “一人一图”收敛，未做真人识别。
